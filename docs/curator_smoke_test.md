# Samar's 1.3 staging smoke test

Use **https://promop-staging.onrender.com** with your usual doctor/curator account. Allow about 45 minutes. Use designated synthetic/demo patients; label new findings "Samar smoke test" and record the patient IDs so test entries can be cleaned up. Do not enter real patient information. Mapping edits affect everyone on staging: approve only a mapping you actually agree with, or use an agreed test mapping.

For each task, record **Pass / Bug / Clinical decision needed / Could not test**. The distinction matters: an unsupported negative inference is a bug; choosing new clinical rules is a separate decision.

| ID | What to do | What to check |
| --- | --- | --- |
| G1 | Open one breast-cancer, one CLL and one myeloma demo patient. Visit Genomics. | The patient and disease are correct. Priority markers are relevant, PALB2 is spelled correctly, and empty markers do not claim a detected or negative result. Note missing/inappropriate marker suggestions for clinical review. |
| G2 | On a designated test patient, add a TP53 finding with present status, a clinically sensible synthetic variant, interpretation, test date and laboratory. Save, navigate away, return and reload. | The finding appears once; gene, source wording, interpretation, date and laboratory survive unchanged. The priority and general finding views agree. |
| G3 | Edit that finding: add distinct transcript DNA and genomic DNA descriptions, a protein change, VAF with an explicit unit, and clone fraction if appropriate. Save and reload. | The independent descriptions stay separate. VAF and clone fraction are not substituted for each other or silently rescaled. Long source descriptions are preserved. |
| G4 | Change the finding from present to absent, then indeterminate, then present again. Inspect it after each save. | Each state survives reload. Absent clears incompatible variant-level values such as VAF. Indeterminate is not displayed as detected or negative. Cleared values do not silently return. |
| G5 | Compare a patient with no TP53 evidence, your qualifying positive finding, and an absent/indeterminate finding. | The aggregate is unknown without qualifying positive evidence. Absence of evidence must not become "No TP53 disruption." A TP53 mutation must not automatically create a del(17p) finding. |
| G6 | Add a second finding with a different report/date. Edit and delete only the first test finding. | The second finding survives. Deletion removes the first from active lists after reload. Source/provenance details are available for the retained finding. Note any unclear distinction between separate tests or findings. |
| M1 | Open **Field Mappings** (`/field-mappings`). Search for a genomic parent field and an individual component such as interpretation or VAF. | Field labels, definitions, mapping status, destination and code are understandable. The concept describes the field/question intended; it is not confused with an answer such as "Pathogenic." |
| M2 | For one field you are authorized to curate, search for a known appropriate concept. Inspect its name, vocabulary, code and domain; save a justified assignment or proposal, then reopen it. | The exact selected code and review status persist. A suggestion is not silently approved. An approved assignment is clinically appropriate for the field and its storage domain. Record questionable suggestions instead of approving them to make a box editable. |
| M3 | Go to **Field Mappings**, pick a field that has bounded answers (e.g. `estrogen_receptor_status`), and open its **Choices** panel. Pick two choices and expand their attached vocabulary codes. Verify each code actually represents the answer it is attached to (e.g. the code on "Positive" should mean positive, not negative). If you find a genuine mismatch, correct it, save, and reopen the panel to confirm the fix persisted. | (1) Each vocabulary code matches the meaning of the choice it is attached to. (2) Choices from one field do not appear in another field's list. (3) Labels and code bindings survive a save/reopen round-trip. (4) "Unknown", "Not tested", "Negative" and "Unmapped" are mapped to distinct codes — not accidentally collapsed into the same concept. |
| M4 | On a test patient, save a value through an already supported mapped field, then reload and inspect its available source details. | The saved value and unit remain correct. Curation does not unexpectedly rewrite unrelated existing patient values. Record the exact field if a displayed choice cannot be saved or read back. |
| O1 | Open the cytogenetics section and the Genomics section for the same patient. Edit one supported test finding. | There is one understandable editing path, no duplicate active finding created by switching views, and original legacy wording/history remains distinguishable from structured entries. |
| O2 | On a suitable lymphoma demo patient, change FLIPI or GELF assessment inputs and reload. | Inputs persist and any displayed score/result agrees with the entered inputs. Derived results are clearly distinguished from directly entered findings; record unexpected calculations with the complete input set. |
| O3 | Add or edit one treatment line with therapy, date and outcome on a test patient. Reload, then revisit Genomics. | Treatment details stay on the intended line, dates/outcomes persist, and genomic findings are unchanged. |
| O4 | Edit one supported laboratory value with a known unit and date. Save and reload; then switch between two test patients. | Numeric value, unit and date remain correct. No patient's values appear on the other patient's record. Report unexpected conversion or rounding with before/after values and units. |
| O5 | Check that your expected clinical and curation controls are available. Log out and revisit a patient page. | Your role permits the intended edits, derived/read-only controls are explained, and logout prevents further authenticated patient access. Report missing permissions without changing roles to work around them. |

The broader reviewed field/value mapping system is still being developed. M3 checks the existing choice/code editor; it does not certify that every choice already projects to a coded OMOP result. Report the specific field/value pair where this is missing. Automated report imports, specimen management, inferred assay negatives and new complex-karyotype rules are outside 1.3 scope.

For each bug, send: task ID, synthetic patient ID, page/field, steps, expected result, actual result, approximate time, and a screenshot if useful. For mapping concerns, include the vocabulary and code. Prioritize wrong patient/value/unit, lost findings, unknown becoming negative, and unjustified positive results over cosmetic issues.

Clinical decisions to record separately: disease-specific marker additions/removals, whether source example wording is valid, marker-specific absence rules, and when combined TP53/del(17p) or complex-karyotype conclusions would be justified. Do not approve new inference rules solely because a smoke test can display them.
