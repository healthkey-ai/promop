# Derivation Changelog

Tracks changes to PatientRecord derivation logic in
`omop_core/services/patient_record_service.py`. Bump `DERIVATION_VERSION`
whenever aggregation or computation logic changes, then add a row here.

After bumping, review the entry's rollout constraints before any authorized
`python manage.py backfill_patient_records` run to re-derive stale records.

| Version | Date       | Description                                      |
|---------|------------|--------------------------------------------------|
| 1       | 2026-07-31 | Baseline — all existing derivation logic          |
| 2       | 2026-08-03 | Add per-line therapy-class ("type") concept_ids (`*_therapy_type_ids`) via HemOnc `Is a`→Component Class expansion (ADR 0002) |
| 3       | 2026-08-10 | Preserve hand-entered values for derived fields the write-through cannot push to OMOP (`user_edited_fields`); read ECOG/Karnofsky from `measurement` as well as `observation`; stop deriving `patient_age` from the `year_of_birth=1900` registration placeholder (#434) |
| 4       | 2026-08-11 | Split HRV into SDNN and RMSSD (#438). Adds `hrv_rmssd_avg_30d`; `hrv_sdnn_avg_30d` no longer receives Garmin values, which were RMSSD filed under a SDNN concept. Garmin-sourced records will show `hrv_sdnn_avg_30d` drop to null and `hrv_rmssd_avg_30d` populate only after the device export is re-uploaded — the mis-filed OMOP rows are not automatically repairable (see #442). Note `hrv_rmssd_avg_30d` is **not** exposed in the `patient_info` compatibility view, whose column list is frozen at migration 0104 (see #448) — external view consumers see Garmin HRV go null with no replacement |
| 5       | 2026-08-14 | Derive `date_of_birth` from OMOP `Person` birth fields, with partial/invalid dates normalized to January 1 (#456). This makes API `age` available for ETL-loaded patients and calculates it without the previous year-only off-by-one. |
| 6       | 2026-09-14 | Read explicit disease-profile source facts, preserve follicular grades 3A/3B, and compute FLIPI/GELF from assessed checklists (#1267). Preserve numeric historical FLIPI results when no factors are recorded; pending explicit clears continue to supersede their legacy OMOP source. |
| 7       | 2026-09-14 | Normalize ANC and platelets to 10³/µL across coded, source-only, legacy-name and approved mapping paths (#640). Latest missing/unsupported units and empty results suppress older values. ANC legacy values carry 10³/µL; integer platelet legacy values carry cells/µL. Preserve raw OMOP facts and pending edits. Review the [rollout plan](clinical-unit-policy.md#anc-and-platelet-rollout-640) before backfilling. |
| 8       | 2026-09-14 | Preserve the existing positive TP53 aggregate rule; return null instead of an unsupported false when no finding qualifies (#1240). No negative-result or del(17p) rule is added. Review the [consumer contract and rollout](genomics_architecture.md#genomic-features-and-finding-terminology) before rederiving persisted rows. |
| 9       | 2026-09-15 | Correct Ki-67 percentage to LOINC 29593-1 and methodology to 85069-3. Stop ER results populating Oncotype/methodology and perineural invasion populating nodal status; block the same wrong-code curated recipes without rewriting curator records or clinical facts (#1227). Run `report_breast_mapping_impact` and review source evidence before any backfill; historical mislabeled facts are not automatically relabeled. |
| 10      | 2026-09-27 | Keep legacy ANC and ALC values in cells/µL when canonical counts are in thousands/µL; mirror hemoglobin from its canonical field (#1567). Migration 0265 repairs existing PatientRecord aliases wherever a canonical value exists, leaving legacy-only and pending user-edited aliases untouched. New derivations and direct edits use the same scale and clear aliases with their canonicals. |
| 11      | 2026-10-07 | Choose the primary cancer as the one being treated, not the latest diagnosis (#1738). Among cancer conditions, prefer one not resolved (ended, or resolved/inactive/history/rule-out status), then one with a current line of therapy, then one with any line, then one not in remission, then the most recent. Lines are attributed through their Disease Episode (#1739); unparented lines belong to the primary the record already held. `condition_clinical_status` now comes from the primary cancer when there is one, not from the latest condition. Single-cancer records derive as before. Re-deriving moves `disease`, `disease_slug`, `diagnosis_date` and the flat therapy fields back to the treated cancer for patients whose latest cancer has resolved. |
| 12      | 2026-10-11 | Use approved FieldConceptMapping destinations and approved SCCM LOINC aliases for lab projection (#1796). The latest recognized result wins across canonical and alias codes; an older exact FCM result no longer overwrites it. Migration 0285 approves unambiguous extractor aliases without changing curator decisions. Existing Measurement facts are not rewritten; re-derive PatientRecords to update persisted flat lab fields. |
| 13      | 2026-10-11 | Derive the language summary and all eight language capabilities exclusively from `PersonLanguageSkill` (#1634). Refresh drops historical `user_edited_fields` markers for these columns and clears `languages_skills` when the last skill is removed. Backfill stale records to repair previously accepted direct edits. |
| 14      | 2026-10-13 | Populate `blood_type` from the latest valid LOINC ABO/Rh Measurement results. Choose the latest combined or ABO result by event datetime/date and ID, combining separate ABO with the latest Rh result. Clear the projection when its source is removed; retain pending user edits through the existing refresh rules. The blood type migration backfills existing PatientRecords without a full clinical re-derivation. |
| 15      | 2026-10-22 | Leave `therapy_lines_count` and `prior_therapy` null when no line of therapy is established, instead of manufacturing `0` / `None` (#1925). An explicit zero, a user-reported count and text-named lines still count as before; relapse and refractory fields are still computed. Re-deriving clears the asserted "no prior therapy" from records that only lacked evidence; matchers then see unknown rather than a negative. |
| 16      | 2026-10-22 | Apply assertion-source precedence to approved mappings too. An older exact Observation mapping no longer overwrites a newer Measurement answer for consent, caregiver availability, contraception, pregnancy, inverse risk or refractory questions; a reviewed mapping to another concept is still read when no assertion-code row answers the field. Only a strictly older mapping is suppressed: an equal-date reviewed mapping still wins, because ids from different tables are not comparable. A newer unusable answer still leaves the field unknown instead of resurrecting an older one, and pregnancy answer/date come from the same fact. Inverse `no_*` field writes now store the opposite raw source answer when the mapping uses the reviewed inverse assertion code, while an alternative approved concept keeps its own polarity; the curated read applies the same reviewed polarity, and refractory inference respects Measurement-backed assertions (#1905). Re-derive stale records with `backfill_patient_records`; no OMOP facts are rewritten. |
| 17      | 2026-10-22 | Keep the latest dated source row in the remaining extractors that predate the #1905 precedence rule (#1907). HIV/hepatitis B/C status now reads the newest recognized result across the concept-code/source-value union instead of the oldest; tobacco status uses the newest question/answer observation and, for legacy SNOMED codes, the newest row regardless of code; behaviour measurements (sleep, exercise, diet, alcohol use) take the newest union row; CLL stage/burden/activity/involvement observations, clonal counts and Richter transformation, plus lymphoma FLIPI/GELF, keep the newest dated row per field; and MM plasma-cell-leukemia, bone-lesion and CRAB facts merge Measurement and Observation, letting the newest usable row win across both tables. An unusable or empty newer answer is skipped, so an older usable answer can still supply the field rather than a fabricated negative (empty or unrecognised CLL boolean, unrecognised MM string) or a concept label, and a zero clonal count is kept as a real answer. Approved-mapping (curated) precedence for these fields is unchanged and still runs after the extractors. Re-derive stale records with `backfill_patient_records`; no OMOP facts are rewritten. A `tumor_burden`, `disease_activity` or `gelf_criteria_status` Observation with no value no longer stores its concept label as the answer; it is skipped so an older real answer can win. |
| 18      | 2026-10-22 | Make IMWG measurable-disease FLC boundary checks exact (`0.26`/`1.65` inclusive) and carry FLC unit conversion in Decimal, so mg/dL values such as 10.23/6.2 do not become 1.6500000000000001 via binary floats (#1928). Apply the same conversion on the legacy display-name path, leave FLC unknown when the latest unit is unsupported (rather than using raw or stale values), and treat non-finite/negative concentrations as unknown. Compute kappa/lambda ratios only from a pair from the same lab event (measurement_event_id, visit+timestamp/date, or timestamp/date proxy); do not combine separate draws. Backfill records that held the old boundary misclassification or an unpaired ratio. |
| 19      | 2026-10-24 | Decode the versioned clinical source-input contract using strict provenance, units and answer slots, retaining raw clear tombstones and deterministic latest date/ID selection. Nullable ULN/swallowing projections remain unknown without compatible facts; SDK SCT clears mask older legacy-source dates without deleting history. Invalid latest answers do not resurrect older results or resolve pending clears. No clinical formula or OMOP fact is rewritten. Full re-derivation requires scoped projection-impact review before separately authorized backfill; see the [rollout plan](cb_clinical_inputs_plan.md#rollout-remains-gated). |
